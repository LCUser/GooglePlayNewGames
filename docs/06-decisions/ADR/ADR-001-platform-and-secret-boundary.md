# ADR-001：客户端平台与 API 密钥边界

- 状态：已批准
- 提出人：Codex（资深 iOS 软件开发 AI）
- 提出日期：2026-11-20
- 审核人 / 审核日期：用户 / 2026-11-20
- 关联需求：REQ-001、REQ-002
- 关联设计：TECH-DOC-001、TECH-IF-001、TECH-REVIEW-001

## 背景

项目已批准以 iOS 和 Xcode 16.1 为开发基线，SwiftUI 优先。上游 playapi.info 的受保护接口要求 API Key。本 ADR 记录用户批准的最低 iOS/Swift 版本、依赖和凭据边界方案。项目仅交付本地可运行版本，不在 App Store 上架；用户明确选择由 App 本地加密保存密钥并直接请求上游，不建设本机代理、后端代理或生产托管服务。该选择接受密钥可能从本机运行态或客户端二进制中提取的风险。

Apple 的 Xcode 系统要求列明 Xcode 16.1 使用 Swift 6.0 编译器，支持 Swift 6、Swift 5、Swift 4.2 和 Swift 4 语言模式，并支持 iOS 15 及以上部署目标。项目需求不依赖 iOS 17 才提供的系统 API。

## 决策范围

选择首版最低系统与 Swift 语言模式、网络/解码依赖、状态存储方式，以及符合本地交付边界的上游 API 密钥处理方式。

## 候选方案

### 最低系统与语言

- A：iOS 15；Swift 6 语言模式。
- B：iOS 16；使用 Xcode 16.1 的 Swift 6.0 编译器及 Swift 6 语言模式。
- C：iOS 17 或更高版本；Swift 6 语言模式。

### 凭据边界

- A：App 内本地加密保存 API Key，并直接通过 HTTPS 请求上游 API。
- B：受控本机代理进程持有上游 API Key；App 只访问本项目代理（未选）。
- C：不实现受保护 API 请求。

## 已批准决定

1. 最低部署目标设为 **iOS 16.0**。
2. 使用 **Swift 6.0 编译器 + Swift 6 语言模式**；启用完整并发检查，新增并发代码须消除并发安全诊断，确需保留的诊断须说明原因。
3. 使用系统 `URLSession`、`Codable` 与 Swift structured concurrency；不添加第三方依赖。
4. 不使用持久化层；只在内存保存本次列表和当前详情。
5. App 直接通过 HTTPS 请求固定的 playapi.info 上游 API；API Key 在 App 内本地加密保存，并仅由凭据存储/API 客户端读取，不传入视图或 ViewModel。
6. API Key 不得以明文写入源码、资源、plist、构建设置、仓库、日志或截图。加密仅保护静态存储，不保证密钥无法从 App 运行态或客户端二进制提取；实现任务必须验证固定 HTTPS 主机、认证头和日志脱敏。
7. 项目仅交付本地可运行版本，不在 App Store 上架；不建设本机代理、后端代理或生产托管服务。

## 评估依据

- iOS 16.0 足以使用 `NavigationStack` 等 SwiftUI 导航 API，同时比 iOS 17+ 降低最低设备门槛；设计不依赖更高版本系统特性。
- Swift 6.0 语言模式可让首版直接采用 Swift 6 的并发安全规则；相应地，所有权隔离与跨并发域传递的数据类型必须按编译器诊断正确建模并测试。
- 原生 `URLSession`、`Codable` 和并发能力覆盖当前单一上游 API 需求，避免无必要的依赖、升级和供应链面。
- 用户明确选择 App 内本地加密存储，以符合本地运行且不发布的范围；不引入代理进程或生产基础设施。
- 客户端必须在运行时使用上游 API Key，因此本地加密不能防止具有本机访问能力的人从运行态或二进制中提取密钥；该残余风险已向用户说明并由其选择接受。
- 当前需求没有离线、跨次缓存或同步要求，持久化会扩大数据生命周期和测试范围而不满足额外的已批准需求。

## 后果

- App 直接访问固定的 HTTPS 上游接口，凭据存储/API 客户端负责读取本地加密密钥；视图和 ViewModel 不接触密钥。
- 不增加本机代理、后端代理、生产托管或云端运维组件。
- App 不在 App Store 上架；只验收本地运行的 App 到上游 API 调用链路。
- iOS 16.0 会排除 iOS 15 用户；若用户优先考虑更广覆盖，可将最低版本改为 iOS 15 并审核导航/API 兼容方案。
- Swift 6 语言模式会提高并发安全要求，可能需要为隔离边界和 `Sendable` 建模投入额外工作；通过从首版统一采用该模式，避免后续语言模式迁移。
- 不持久化意味着每次完全启动重新加载，符合当前刷新规则且没有离线需求。

## 已批准的其他行为约束

- 详情加载失败时，详情内容区域只显示 `Unable to load games`，保留系统导航返回，不自动重试。
- 列表使用两个目标类别并行请求、每类别顺序分页，页大小 100；无法证明分页完整时整体失败。
- API 日期参数时区/边界语义需在实现前补充验证；客户端仍按本地 Calendar 边界精确过滤。
- 列表字段限标题、图标、类别和本地化首次上架日期；详情仅展示已验证并获用户批准的字段，不使用商店 URL。
