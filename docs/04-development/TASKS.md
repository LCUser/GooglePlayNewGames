## 任务定义

### TASK-001 日期边界与分页终止契约验证

- 目标：补齐实现前仍未由 Gate 2 证据证明的 `/new` 日期边界包络、总量/末页终止条件及可访问上限行为。
- 范围：使用已批准的 API 验证方式进行脱敏请求；验证查询包络不会漏掉设备本地 `D-15` 至 `D-7` 边界候选；验证 `total`、页数、空页及 10,000 条访问上限组合下能否判断完整性；更新 API 验证报告和证据。
- 不包含：App 代码、正式 iOS 页面、跨时段稳定性验证、额外类别/市场筛选、生产服务或代理。
- 依赖：无。
- 验收标准：
  1. 日期验证覆盖 UTC 与本地日期跨日，以及窗口两端临近午夜的样本；结论说明当前查询包络是否足以覆盖需求窗口。
  2. 分页结论明确列出服务端终止判断字段、末页行为和达到 10,000 条时的可判定条件。
  3. 所有请求证据均脱敏，不包含真实 Key、认证头或可复用凭据。
  4. 若 API 无法证明不会漏项或无法判定结果完整性，记录为阻塞项并暂停依赖该契约的 TASK-005，不自行改变需求或显示部分结果。
- 测试 / 证据：API-TC-006、API-TC-009 的补充验证；关联 TC-001、TC-002。
- 交付物：更新后的 API 验证报告及脱敏证据。
- 执行结果（2026-11-20）：日期包络样本验证通过；分页元数据及 10,000 条可访问上限已确认。相同筛选条件在不同请求轮次的 `total` 有变化，完整性判定必须只使用同一轮一致的分页元数据；超过 10,000 条或同轮完整性无法证明时整体失败，不得返回部分结果。证据见 `docs/02-api/evidence/TASK-001-API-BOUNDARY-PAGING-2026-11-20.md`。
- 状态：已完成，用户于 2026-11-20 确认通过；TASK-002 及后续任务尚未启动。

### TASK-002 iOS 工程骨架与启动导航

- 目标：建立可在本机运行的 iOS App 工程和最小 SwiftUI 启动结构。
- 范围：Xcode 16.1 工程、iOS 16.0 最低部署目标、Swift 6.0 语言模式、SwiftUI App 入口、列表到详情的导航容器、测试 target 与可注入依赖的基础组装点。
- 不包含：列表/详情业务 UI、网络调用、业务模型、第三方依赖。
- 依赖：TASK-001 的验证无需阻塞空工程创建；实现顺序上 TASK-001 先完成。
- 验收标准：
  1. 工程在批准工具链下构建并可在 iOS 16.0 及以上模拟器启动。
  2. Swift 6.0 语言模式及完整并发检查启用，无新增第三方依赖。
  3. 启动入口不触发未实现的上游请求；导航结构可由后续任务接入。
  4. 单元测试 target 可运行，基础依赖可替换。
- 测试：TC-003。
- 执行结果（2026-11-20）：Xcode 16.1 下 App 与 XCTest target 均构建成功；Swift 6.0、完整并发检查及 iOS 16.0 部署目标已配置。`AppDependenciesTests.testRootViewFactoryCanBeReplaced()` 在 iOS 18.1 模拟器通过，App 在同一模拟器成功安装并启动。启动入口仅创建根视图和导航结构，不包含网络请求、业务模型或凭据读取。iOS 16.0 是最低部署目标，任务已审核通过。
- 状态：已完成，用户于 2026-11-20 确认通过；TASK-003 及后续任务未启动。

### TASK-003 本地 API Key 配置与受保护存储

- 目标：在不把真实 API Key 纳入 Git 的前提下，为本机运行配置凭据，并由 App 通过受保护存储读取。
- 范围：使用仓库根目录现有 Git 忽略项 `playapi-key.local` 作为本机文本配置源；定义本地运行时读取/注入路径；App 将凭据保存至系统 Keychain（实现建议，须经 Gate 5 批准），API 客户端仅通过凭据接口读取。空配置、缺失配置、写入/读取失败均应形成脱敏错误。
- 不包含：代理、后端、云托管、凭据管理 UI、将真实 Key 写入源码/共享构建配置/测试证据。
- 依赖：TASK-002。
- 验收标准：
  1. `playapi-key.local` 已被 `.gitignore` 忽略；仓库不新增真实 Key。
  2. 本地配置缺失或格式无效时，App 不发送认证请求，界面按已批准失败状态处理。
  3. 有效凭据仅由凭据存储/API 客户端使用；列表视图和 ViewModel 不接触 Key。
  4. 凭据存储使用系统 Keychain，不新增第三方加密依赖；日志、错误、截图和测试断言不包含 Key 或认证头。
  5. 文档准确说明本地配置文件是明文开发配置源，Keychain 保护 App 保存后的静态凭据；不宣称能抵御本机运行态/本地构建产物提取。
- 测试：TC-004、TC-005。
- 待审核实现细节：本机文本文件到本地运行 App 的具体注入/初始化方式应在 TASK-003 实施计划中说明，并确认不会把凭据提交到共享工程配置。

### TASK-004 上游 HTTP 客户端与响应解码

- 目标：实现固定上游主机的认证 HTTP 请求、响应解码和底层错误分类。
- 范围：系统 `URLSession`、`Codable`；实现 `/api/v1/new` 页面请求及 `/api/v1/app` 详情请求所需 DTO；验证 HTTP 状态、必需字段、可空字段和详情 ID 一致性；传输可取消。
- 不包含：日期业务窗口、分页聚合、UI 状态、任意主机请求、外部 URL 跳转、第三方网络库。
- 依赖：TASK-001、TASK-003。
- 验收标准：
  1. 仅向固定 HTTPS 上游主机发送请求；列表仅允许两个已批准类别；详情只传调用方提供的应用 ID。
  2. 按 API 基线使用认证头；不把 Key 放入 URL、错误文本或日志。
  3. HTTP 非成功、传输失败、解码失败、响应结构不符、详情 ID 不匹配均返回可测试的分类错误。
  4. 取消请求会终止底层加载并作为取消处理，不伪装为用户可见失败。
- 测试：TC-006、TC-007、TC-008。

### TASK-005 本地日期窗口与列表数据聚合

- 目标：生成需求规定的本地日历日期窗口，并取得完整、过滤、去重、排序后的列表数据。
- 范围：可注入 `now`、`Calendar`、`TimeZone`；按设备本地 `D-15` 起始至 `D-6` 起始的半开区间生成绝对时刻边界；按已验证 API 日期包络读取两个类别；类别内顺序分页、类别间并行；客户端精确过滤、按 ID 去重并确定性排序；整体原子失败。
- 不包含：页面展示、详情请求、缓存/持久化、后台刷新、用户排序/筛选/搜索。
- 依赖：TASK-001、TASK-004；TASK-001 若未证明日期/分页完整性，本任务不得开始。
- 验收标准：
  1. 第 15 日和第 7 日全部时刻包含，第 16 日与第 6 日排除；正确处理本地午夜、UTC 跨日和 DST。
  2. 只请求 `GAME_PUZZLE`、`GAME_CASUAL`，不传国家/地区过滤。
  3. 两类别可并行，各自分页顺序执行；按已验证终止契约读取。
  4. 客户端以精确绝对时刻过滤，按 ID 去重、`released` 降序；同刻按 ID 升序。
  5. 任一类别/页面失败或完整性无法证明时整体失败，不返回部分集合；完整成功零条时返回空集合。
  6. 取消及过期任务不能发布部分或陈旧结果。
- 测试：TC-009 至 TC-013。

### TASK-006 新游列表界面与启动刷新

- 目标：交付符合需求的列表页面和完全启动刷新生命周期。
- 范围：英文列表 UI、加载/有结果/空/失败状态、行内容、依赖 `GameCatalog`、完全启动一次刷新及取消/旧任务隔离。
- 不包含：搜索、筛选、排序控件、手动刷新、后台回前台刷新、商店跳转、详情字段实现。
- 依赖：TASK-002、TASK-005。
- 验收标准：
  1. 页面只显示目标类别的游戏，按既定顺序呈现；行字段只使用获准模型中的标题、图标、类别和首次上架日期。
  2. 首次完全启动触发一次加载；视图重绘、重复生命周期事件和后台回前台不重复刷新。
  3. 成功零项仅显示 `No games found`；失败仅显示 `Unable to load games`；加载态不出现额外说明文案。
  4. 不出现需求明确排除的控件或入口。
  5. 点击列表项可进入对应详情导航目的地。
- 测试：TC-014 至 TC-016。

### TASK-007 游戏详情读取与详情界面

- 目标：从列表选中项加载并展示对应游戏的详情，不提供外部商店跳转。
- 范围：按所选 `id` 请求详情；校验 ID；展示已验证且在本任务实施前经用户确认的详情字段；加载、成功和失败状态；离开页面时取消未完成请求。
- 不包含：商店 URL、外部跳转、详情搜索/编辑/收藏、自动重试、未验证对象子字段。
- 依赖：TASK-004、TASK-006。
- 建议展示字段：`title`、`summary`、`description`、`recent_changes`、`released`；均限于 API 已验证字段，不展示 `url`。该清单提交 Gate 5 由用户确认。
- 验收标准：
  1. 请求 ID 与所选列表项一致，响应 ID 不匹配时按失败处理。
  2. 仅展示 API 字典/数据模型允许且用户已批准的字段；不把 `url` 暴露为可点击入口。
  3. 详情失败内容区仅显示 `Unable to load games`，保留系统返回导航，不自动重试。
  4. 离开详情后取消请求；迟到响应不覆盖当前页面状态。
- 测试：TC-017、TC-018。
- Gate 5 审核提示：用户可批准上述建议字段或在 Gate 5 指定其他已验证字段；字段清单获批前，本任务不得进入 Ready。
