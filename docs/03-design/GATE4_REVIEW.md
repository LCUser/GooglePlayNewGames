## 2. 架构说明

采用 SwiftUI 单 App target，并按 `GameListFeature`、`GameListViewModel`、`GameCatalog`、`GameAPIClient`、`ReleaseDateWindow` 和 DTO/领域模型职责分层。App 直接请求上游 API，API Key 在 App 本地加密保存，不增加代理组件。列表 ViewModel 只处理冷启动刷新及页面状态；Catalog 并行聚合两个类别、在类别内顺序分页、客户端精确过滤/去重/排序；API Client 负责凭据读取、传输、解码和底层错误分类。详情按列表项 ID 请求 `/api/v1/app`。模块关系与契约详见 `INTERFACE_CONTRACTS.md`。

每次完全启动只刷新一次；前后台恢复不触发自动刷新。两类别及所有必要页完整成功后一次性发布结果，任意失败时整体显示 `Unable to load games`；完整成功但无结果时只显示 `No games found`。需求不要求持久化，方案提议只保留内存状态。

## 4. 供用户拍板的具体选型

以下 1–9 项已由用户批准并记录于 [ADR-001](../06-decisions/ADR/ADR-001-platform-and-secret-boundary.md)。项目交付目标是本地可运行版本，不要求 App Store 发布或生产托管。

1. **最低部署版本：iOS 16.0。** 使用 `NavigationStack`，不依赖更高版本 API；Xcode 16.1 支持 iOS 15 及以上部署目标。若更重视覆盖旧设备，可另议 iOS 15 并审核兼容方案。
2. **Swift：Swift 6.0 编译器 + Swift 6 语言模式。** 启用完整并发检查，新增并发代码须处理并发安全诊断。
3. **并发与系统依赖：** 原生 structured concurrency、`URLSession`、`Codable`；不新增第三方依赖。
4. **API Key：App 本地加密保存。** App 直接请求固定 HTTPS 上游 API，运行时从本地受保护存储读取密钥并添加认证头；不增加代理。加密保存不保证密钥无法从运行态或客户端二进制提取，该方案按本地、不发布的交付范围采用。
5. **存储：** 不做持久化/缓存，仅保留内存中的当前列表和详情。
6. **详情失败：** 详情内容区只显示 `Unable to load games`，保留系统返回导航，不自动重试或提供其他错误操作。
7. **分页：** 每类别 `per=100` 顺序翻页，两个类别并行；达到 API 可访问上限仍不能证明完整时整体失败。实现前用脱敏验证确认 `total`、最后页和上限处理。
8. **日期查询：** 用保守 UTC 日期包络取候选，客户端按本地日历 `[D-15 start, D-6 start)` 精确过滤；实现前验证 API 日期参数边界，证明不会漏掉本地边界数据。
9. **字段：** 列表使用标题、图标、类别、本地化首次上架日期；详情仅显示已验证且用户批准的字段，不显示 URL。

密钥本地加密存储的具体实现及验证标准由阶段 5 任务定义；本项目不涉及代理部署、生产托管、额外云服务费用或生产运维责任。

## 5. 设计验证 / 测试方案

Gate 4 只审核测试设计，不执行 App 实现测试。阶段 5/6 可将以下内容细化为 TC：

| 验证 ID | 层级 | 场景 / 预期 |
|---|---|---|
| TC-DES-001 | 单元 | 固定设备日期与时区，验证本地 `D-15` 起始时刻包含、`D-7` 结束日最后时刻包含，`D-16` 与 `D-6` 排除 |
| TC-DES-002 | 单元 | UTC 时间戳映射本地日期跨 UTC 午夜；结果按本地日历规则而非 UTC 日期截断决定 |
| TC-DES-003 | 单元 | 夏令时切换附近的日期窗口使用 Calendar 日界，含边界不依赖固定 24 小时天数 |
| TC-DES-004 | 单元 | 仅允许两个类别；两类数据按 ID 去重、released 降序、同刻 ID 确定性排序 |
| TC-DES-005 | 单元 | 传输/解码/缺页/分页上限问题被映射为整体失败；不得回传部分集合 |
| TC-DES-006 | 集成 | 每类使用 `per=100` 顺序翻页至终止；页失败导致聚合失败；确认 API 总量/终止字段处理 |
| TC-DES-007 | 集成 | 仅在刷新时并行发出两个目标类别；不发 `GAME`、其他类别、市场过滤参数或商店 URL 请求 |
| TC-DES-008 | 集成 | 详情以被点击应用 ID 请求；映射实测详情字段；404 与其他错误分类稳定 |
| TC-DES-009 | UI | 成功非空只显示目标列表；成功零项仅显示 `No games found`；加载失败仅显示 `Unable to load games` |
| TC-DES-010 | UI / lifecycle | 冷启动触发一次请求；视图重绘、同次重复启动和后台回前台不引发重复刷新 |
| TC-DES-011 | 并发 | 取消刷新/详情任务后旧响应不能覆盖新状态；取消本身不显示失败信息 |
| TC-DES-012 | 安全 | 仓库、源码、资源、日志及截图无明文 API Key；验证 App 本地加密存储和 HTTPS 认证头不泄露凭据 |
| TC-DES-013 | 手工验收 | 英文界面；列表可进入详情；全流程无登录、搜索、筛选、收藏、分享、外部跳转、付费、同步或通知入口 |

日期验证使用固定 `now`、不同设备时区（例如 UTC 与 UTC-08:00）、午夜附近的 UTC `released` 样本及 DST 转换样本。API 验证只在获准的验证环境执行，不将真实凭据写入证据。

## 6. 风险

| 风险 | 影响 | 缓解 / Gate 处理 |
|---|---|---|
| App 本地密钥可能从运行态或二进制提取 | 本地 API Key 泄露并被他人使用 | App 不发布；本地加密仅保护静态存储，不宣称抵御本地运行态提取；禁止明文提交或记录密钥 |
| API 日期参数服务端时区语义未证实 | UTC 查询可能漏掉本地窗口边界记录 | 增补针对性 API 验证；客户端始终二次精确过滤 |
| 分页端点最多可访问 10,000 条且全量终止契约不完整 | 可能出现静默截断或不完整列表 | 记录 total/页数，验证终止语义；疑似截断则失败而不展示部分数据 |
| API 子对象仅容器级验证 | 模型解码/详情 UI 可能基于猜测 | 初版不依赖未验证子字段；需要时先验证再纳入 |
| 详情错误需求未规定 | 实现自行选择可能扩展或偏离需求 | 按已批准合同显示 `Unable to load games`，保留系统返回，不自动重试 |
| Swift 6 语言模式的并发安全要求较严格 | 可能增加隔离边界和 `Sendable` 建模工作 | 从首版采用 Swift 6 模式；按编译器诊断实现并验证 |
