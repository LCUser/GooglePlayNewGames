## 2. 架构说明

建议采用 SwiftUI 单 App target，并按 `GameListFeature`、`GameListViewModel`、`GameCatalog`、`GameAPIClient`、`ReleaseDateWindow` 和 DTO/领域模型职责分层。列表 ViewModel 只处理冷启动刷新及页面状态；Catalog 并行聚合两个类别、在类别内顺序分页、客户端精确过滤/去重/排序；API Client 负责传输、解码和底层错误分类。详情按列表项 ID 请求 `/api/v1/app`。模块关系与契约详见 `INTERFACE_CONTRACTS.md`。

每次完全启动只刷新一次；前后台恢复不触发自动刷新。两类别及所有必要页完整成功后一次性发布结果，任意失败时整体显示 `Unable to load games`；完整成功但无结果时只显示 `No games found`。需求不要求持久化，方案提议只保留内存状态。

## 4. 待用户决策项

请在 Gate 4 审核时逐项给出决定；可在文档中直接注明“批准 / 修改 / 暂不决定”及意见。

1. **API Key 生产调用架构（阻断后续实现）**：选择并批准服务端代理/API 网关及其运行维护责任；或指定其他不把共享秘密嵌入 App 的方案。若首版没有可用的安全凭据方案，需决定是否暂停受保护 API 调用相关开发。仅供本机的临时开发密钥是否允许及其注入方式也须明确，不得默认把密钥写入源码/配置文件。
2. **详情失败 UI**：REQ-002 未指定详情加载失败/404 的可见文案与行为。是否允许详情页使用一个详情专属错误提示，还是将列表的“错误时只显示 Unable to load games”解释为全 App 统一状态约束？是否允许返回列表的导航操作属于页面行为决策。
3. **最低 iOS 部署版本**：请给出明确版本，或授权后续用所选 Xcode 16.1 和最终 API 需求提出兼容性建议再审批。
4. **Swift 语言与并发模式**：请确定 Swift 版本/语言模式及并发检查策略，或留待 Gate 5 前依据部署目标提交具体选项。
5. **系统与第三方依赖**：是否批准系统 `URLSession`、`Codable`、原生 Swift 并发且不新增第三方依赖。
6. **持久化**：是否批准首版仅内存状态，不做缓存/离线读取。
7. **分页终止与 10,000 上限策略**：是否批准每类别顺序读取、在可访问上限仍可能有余项时整体失败；是否要求在开发前补做 API 验证以确认响应总数、最后一页与页大小变化契约。
8. **日期查询包络验证**：是否批准先以保守 UTC 日期包络取候选、客户端本地日历绝对时刻二次过滤，并在 Gate 5/开发前通过边界 API 验证证明不会漏数。
9. **列表展示字段**：是否批准列表展示标题、图标、类别和本地化首次上架日期。详情最终展示字段待根据用户确认与 API 已验证子字段确定；不批准的字段不展示。

## 5. 设计验证 / 测试方案

Gate 4 只审核测试设计，不执行 App 实现测试。阶段 5/6 可将以下内容细化为 TC：

| 验证 ID | 层级 | 场景 / 预期 |
|---|---|---|
| TC-DES-001 | 单元 | 固定设备日期与时区，验证本地 `D-15` 起始时刻包含、`D-7` 结束日最后时刻包含，`D-16` 与 `D-6` 排除 |
| TC-DES-002 | 单元 | UTC 时间戳映射本地日期跨 UTC 午夜；结果按本地日历规则而非 UTC 日期截断决定 |
| TC-DES-003 | 单元 | 夏令时切换附近的日期窗口使用 Calendar 日界，含边界不依赖固定 24 小时天数 |
| TC-DES-004 | 单元 | 仅允许两个类别；两类数据按 ID 去重、released 降序、同刻 ID 确定性排序 |
| TC-DES-005 | 单元 | 传输/解码/缺页/分页上限问题被映射为整体失败；不得回传部分集合 |
| TC-DES-006 | 集成 | 每类使用 `per=100` 顺序翻页至终止；页失败导致聚合失败；确认 API 总量/终止字段处理 |
| TC-DES-007 | 集成 | 仅在刷新时并行发出两个目标类别；不发 `GAME`、其他类别、市场过滤参数或商店 URL 请求 |
| TC-DES-008 | 集成 | 详情以被点击应用 ID 请求；映射实测详情字段；404 与其他错误分类稳定 |
| TC-DES-009 | UI | 成功非空只显示目标列表；成功零项仅显示 `No games found`；加载失败仅显示 `Unable to load games` |
| TC-DES-010 | UI / lifecycle | 冷启动触发一次请求；视图重绘、同次重复启动和后台回前台不引发重复刷新 |
| TC-DES-011 | 并发 | 取消刷新/详情任务后旧响应不能覆盖新状态；取消本身不显示失败信息 |
| TC-DES-012 | 安全 | 构建配置、源码、资源、日志及截图无 API Key；凭据经批准的安全边界注入 |
| TC-DES-013 | 手工验收 | 英文界面；列表可进入详情；全流程无登录、搜索、筛选、收藏、分享、外部跳转、付费、同步或通知入口 |

日期验证使用固定 `now`、不同设备时区（例如 UTC 与 UTC-08:00）、午夜附近的 UTC `released` 样本及 DST 转换样本。API 验证只在获准的验证环境执行，不将真实凭据写入证据。

## 6. 风险

| 风险 | 影响 | 缓解 / Gate 处理 |
|---|---|---|
| 客户端认证密钥可被提取，服务端架构未定 | 无法安全交付可调用受保护 API 的 App | Gate 4 先定凭据边界；否则暂停相关实现 |
| API 日期参数服务端时区语义未证实 | UTC 查询可能漏掉本地窗口边界记录 | 增补针对性 API 验证；客户端始终二次精确过滤 |
| 分页端点最多可访问 10,000 条且全量终止契约不完整 | 可能出现静默截断或不完整列表 | 记录 total/页数，验证终止语义；疑似截断则失败而不展示部分数据 |
| API 子对象仅容器级验证 | 模型解码/详情 UI 可能基于猜测 | 初版不依赖未验证子字段；需要时先验证再纳入 |
| 详情错误需求未规定 | 实现自行选择可能扩展或偏离需求 | Gate 4 明确可见错误合同 |
| 最低系统、Swift 版本与依赖未定 | 影响 API 可用性、并发写法及构建设置 | Gate 4 记录决定，之后再形成实现任务 |
